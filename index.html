Teacher Discussion: When can the client access the database directly?

In the recommended three-tier architecture, Rule R-03 (Client → Database :3306) is set to DENY. If an administrator changes Rule R-03 to ALLOW (or if an untrusted network rule allows direct access):

  • The packet travels directly: The simulated firewall lets the client connect straight to 10.0.3.10:3306.
  • Why people mistakenly do it: Small office setups or developer convenience (e.g. running local MySQL Workbench, direct reporting, or legacy scripts).
  • Catastrophic security risk: It completely bypasses authentication and validation in the Application Tier, exposes database ports to brute-force attacks, and risks data exfiltration if the client subnet is compromised.

Use the Policy Analyzer tab to see how automated rules-engines flag this as a critical tier-bypass violation!

Least privilege in the recommended baseline

Servers can talk to the next tier only when they need to. The baseline never exposes the database directly to the client or web tier. This simplified model matches endpoints and port; TCP and UDP selections share the same rules.

Why three tiers?

Separating the web, application and database responsibilities limits the blast radius of an attack and makes each layer easier to secure, scale and understand.
