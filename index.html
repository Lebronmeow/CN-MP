Architectural Trade-offs: Two-Tier vs Three-Tier

Engineering evaluation
MODE A

Two-Tier (Client-Server)

Direct client connection to MySQL via TCP port 3306. Web and application layers are bypassed.

Advantages (+)

  • Ultra-Low Latency: Direct binary TCP socket yields ~0.51ms mean query time (~23x faster than Mode B).
  • Zero Intermediate Overhead: No JSON serialization/deserialization or REST translation layers.
  • Operational Simplicity: Fewer services and moving parts to orchestrate or troubleshoot.

Trade-offs & Constraints (-)

  • Credentials on Client: Database credentials (client_user) must be provisioned on client endpoints.
  • Exposed DB Port: Port 3306 must be accessible across the network, widening the database attack surface.
  • No Central Business Logic: Validation and business rules are compiled into client binaries, hindering updates.
Real-World Applications:

LAN Accounting Software (e.g., Tally ERP multi-user), Dental & Clinic Desktop POS workstations, hospital billing terminals talking to an on-premise SQL server.

MODE B

Three-Tier (Web-App-DB)

Segmented perimeter: Client → Nginx TLS (443) → FastAPI (5000) → MySQL (3306).

Advantages (+)

  • Defense-in-Depth: Database is in an isolated subnet (10.0.3.0/24) with zero direct client access.
  • Centralized Logic & Security: Database schema, credentials, and business logic stay strictly on backend tiers.
  • TLS Termination: Public communication is encrypted (TLS 1.3); private queries remain internal.
  • Horizontal Scalability: Web and API tiers can be scaled independently behind load balancers.

Trade-offs & Constraints (-)

  • Higher Latency: Multi-hop routing, TLS negotiation, and JSON serialization introduce ~11.8ms mean latency.
  • System Complexity: Multiple container layers, routing rules, and reverse proxies to monitor and secure.
  • Higher Resource Consumption: Higher memory and CPU footprint across multiple distinct services.
Real-World Applications:

E-commerce platforms (Amazon, Shopify), Internet Banking portals, multi-tenant SaaS platforms requiring strict tenant data isolation.

IP Subnet 10.0.x.0/24

Isolated broadcast domains. Each tier sits in its own /24 subnet, requiring the firewall router to forward packets.

Service Port :3306, :443

Specific TCP/UDP socket doors. In Mode A, port 3306 is open to clients; in Mode B, only port 443 is permitted.

Stateful Inspection

Linux conntrack tracks TCP handshakes so ESTABLISHED response packets return automatically without opening inbound ports.

End-to-End Latency Benchmark (100 Iterations)

Comparing 100 direct MySQL queries (Mode A) vs 100 HTTPS requests through Nginx → FastAPI → MySQL (Mode B).

⚡ Mode A is 23.2x Faster
Mode A (Two-Tier) Mean 0.51 ms Median: 0.26ms · P95: 0.37ms
Mode B (Three-Tier) Mean 11.81 ms Median: 10.77ms · P95: 12.90ms
Overhead Attribution +11.30 ms TLS handshake + JSON serialization + 2 hops
Why does Mode B have higher latency?

Two-tier speaks the direct binary MySQL wire protocol across one router hop. Three-tier requires TLS 1.3 key exchange at Nginx, HTTP request parsing, JSON serialization in FastAPI, and an internal connection to MySQL across three distinct subnets. Enterprises intentionally accept this ~11ms latency overhead to achieve perimeter segmentation and prevent client tampering.
